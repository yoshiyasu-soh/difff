# difff の Cloudflare Workers & Pages 移植 設計書

- 作成日: 2026-08-14
- 対象: [original-source/difff-master](../../../../original-source/difff-master/) (Perl CGI) を Cloudflare Workers 上に移植する
- ステータス: 承認待ち

## 1. 背景と目的

difff《ﾃﾞｭﾌﾌ》は2つのテキストの差分を文字単位（英単語は単語単位）でハイライト表示するウェブツール。オリジナル実装は Perl CGI + UNIX `diff` コマンド + FIFO（名前付きパイプ）で構成されており、そのままでは Cloudflare Workers 上で動作しない。

本ドキュメントは、ロジックを忠実に移植しつつ UI をモダン化し、差分計算をクライアント側（ブラウザの Web Worker）で行う構成への移植設計をまとめる。

## 2. 移植方針のサマリ

ブレインストーミングで合意した方針:

1. **ロジック忠実 + UI モダン化** — 差分検出アルゴリズムの結果はオリジナルと可能な限り同一に保つ。見た目・HTML/CSS はレスポンシブ・ダークモード対応で書き直す。
2. **公開機能（save.cgi/delete.cgi 相当）を移植する** — Workers KV を使い、TTL 3日で結果を保存・公開URL発行・パスワード削除に対応する。
3. **差分計算はクライアント側（Web Worker）で実行する** — 実測の結果、Cloudflare Workers 上でサーバ計算すると CPU 時間制限（Free: 10ms/req）に抵触するため。詳細は §4 に記載。
4. **ホスティング構成は Workers 単体 + Static Assets** — デプロイ単位を1つにまとめ、`wrangler.jsonc` の `assets` 設定で静的ファイルを配信し、同じ Worker が `/api/*` と公開ページの SSR を担当する。
5. **日英両対応を維持する** — オリジナルの `difff.pl` / `en/difff_en.pl` はロジック同一・文言のみ差分のため、共通エンジン + メッセージカタログ (`src/i18n/`) で吸収する。

## 3. 全体アーキテクチャ

```
ブラウザ                                    Cloudflare Worker
┌─────────────────────────┐              ┌──────────────────────┐
│ main.ts (UI)            │              │ index.ts (ルーティング) │
│   ↓ postMessage         │  POST /api/  │   ├ save.ts  → KV書込 │
│ diff.worker.ts ─→ core/ │ ───────────→ │   ├ delete.ts→ KV削除 │
│   ↑ 結果                │              │   └ page.ts  → shell  │
└─────────────────────────┘              └──────────────────────┘
                                                    ↓
                                         Workers KV (TTL 3日)
```

差分エンジンはプラットフォーム非依存の純粋 TypeScript モジュール (`src/core/`) として実装し、DOM や Cloudflare API に依存させない。ブラウザ・Web Worker・Cloudflare Worker（公開ページの SSR プレビュー用途）のどこからでも同一コードを呼べるようにする。

**Cloudflare Worker は差分計算を一切行わない。** 保存・削除・公開ページの外殻返却のみを担当し、CPU 時間は数ミリ秒に収まる（Free プランの 10ms 制限内で運用可能）。

## 4. 差分計算をクライアント側で行う根拠（spike 実測結果）

Node.js (V8) 上で純粋 TypeScript 実装の Myers 差分（線形空間版）を実測した。

### エンドツーエンド所要時間（トークン化 → diff → HTML生成、日本語テキスト）

| 文字数 | 編集率1% | 編集率5% | 編集率10% | 編集率30% |
|---:|---:|---:|---:|---:|
| 10,000 | 6ms | 10ms | 21ms | 96ms |
| 50,000 | 20ms | 83ms | 272ms | 2,236ms |
| 100,000 | 40ms | 271ms | 934ms | 9,974ms |

- メモリ: 差分計算のヒープ増分は最大でも約20MB、ピークRSS 106MB（Node実行時の基礎消費込み）。線形空間版 Myers のため入力サイズに対して概ね線形。
- 正当性: ランダム生成した3000ケースで「復元可能性」「編集距離の最小性」を素朴DPと突き合わせて検証済み（失敗0件）。

### Cloudflare Workers の CPU 時間制限との比較

| プラン | CPU上限 | 実測との関係 |
|---|---|---|
| Free | 10ms/リクエスト | 1万文字・編集率1%（6ms）でギリギリ。編集率10%（21ms）で制限超過 |
| Paid ($5/月) | 既定30秒（設定で延長可） | 動作するが、大きな入力を投げるだけで CPU時間課金を膨らませられる攻撃面が残る |

**結論**: サーバ側で計算すると Free プランでは実用にならず、Paid プランでも DoS 的な課金攻撃の面がある。クライアント実行なら計算コストはユーザー端末に閉じ、Worker 側のコストは保存・削除・配信のみに限定できる。

### 対策

- 差分計算を **Web Worker** 上で実行し、メインスレッドをブロックしない。UI 側で進捗表示・キャンセルボタンを提供する。
- 各テキスト **10万文字**を超えたら警告を表示する（オリジナルは合計5MBの入力上限を持っていた）。
- 行アンカリング最適化（行単位で先に diff し、変化ブロックのみ文字単位で再比較）は**採用しない**。実測で編集率10%では高速化するが、編集率30%ではかえって遅くなり（12.4秒 vs 10.5秒）、かつ最適化なしでも現実的なユースケース（編集率1〜10%）は1秒未満に収まるため、複雑さに見合わない。必要になれば後日追加できる設計にする。

## 5. 差分エンジンの設計（オリジナルとの対応）

| # | オリジナル (`difff.pl`) | 移植後 | 忠実度 |
|---|---|---|---|
| 1 | `escape_char()` — `& < > ' "` を実体参照化 | 同一ロジック | 完全 |
| 2 | 改行を `<$>` マーカーに置換 | 内部表現は行配列に変更（クラス外部への影響なし） | 等価 |
| 3 | `/^([a-z]+\|<\$>\|&#?\w+;\|.)/` でトークン分割 | 同一の正規表現をそのまま踏襲 | 完全 |
| 4 | `diff -d` を FIFO 経由で実行 | 線形空間 Myers 差分アルゴリズムを自前実装 | 下記注記① |
| 5 | `c`/`d`/`a` の行番号レンジから `<em>` 挿入 | Myers の ops（`=`/`-`/`+`）から直接マーキング | 等価 |
| 6 | `<$>` を複製して左右の改行数を揃える処理 | ops から行ペアを直接構築 | 下記注記② |
| 7 | `<em>` が `<td>` をまたぐ場合の分割処理 | 行ペア構築時に自然に解消 | 等価 |
| 8 | `</em>` 直前の空白を `&nbsp;` 化 | 同一ロジック | 完全 |
| 9 | `count_char()` — 文字数/空白込み/改行込み/単語数の4指標 | 同一ロジック | 完全 |

### 注記① Myers 法と GNU diff の同点解

Myers 法の最小編集距離は一意だが、同じ距離を与える編集手順が複数存在する場合の選び方は実装依存であり、GNU diff の出力と完全一致する保証はない。「最小であること」「復元可能であること」は3000ケースの property-based テストで検証済み。加えてオリジナル（Perl + GNU diff）の実出力と突き合わせるゴールデンテストを実装フェーズで用意し、実際の差異があれば可視化・記録する。

### 注記② 行合わせロジックの正攻法への置き換え（意図的な逸脱）

オリジナルの「`<$>` を探して複製する」処理（[difff.pl:85-91](../../../../original-source/difff-master/difff.pl#L85-L91)）は、`diff` のテキスト出力を後処理する都合で生まれた実装であり、条件次第で左右の行がずれる場合がある。

移植版では差分の ops を直接保持しているため、左右の行ペアを diff 結果から素直に構築する。**差分の検出結果（どこが変更されたか）は変えず、表示時の行合わせ処理だけをより堅牢な実装に置き換える。** UI モダン化の範囲内の変更として扱う。

### トークン化の癖について

オリジナルの `[a-z]+` は**小文字のみ**をまとめてトークン化するため、`Betty` は `B` + `etty` に分割される。これは意図的にオリジナルの挙動を維持する（直すと差分の粒度が変わり、既存ユーザーが慣れた挙動と結果が変わってしまうため）。

## 6. 公開機能（save/delete 相当）の設計

### 保存するデータ

**レンダリング済み HTML ではなく、元テキストを保存する。**

```
key:   page:<5文字ID>
value: {
  v: 1,
  lang: "ja" | "en",
  a: string,          // sequenceA 原文
  b: string,          // sequenceB 原文
  salt: string,
  pwHash: string,      // SHA-256(salt + password)
  createdAt: number,   // epoch seconds
}
TTL: 259200 秒（3日）
```

理由:
- クライアント生成の HTML をそのまま保存・配信すると、任意の HTML を POST された場合に自ドメイン上の格納型 XSS になる。
- 元テキストを保存すれば、公開ページも同じクライアント差分エンジンで描画でき、Worker 側の CPU 消費をゼロに保てる（§4 の方針と整合）。

### ID 生成

オリジナルと同じ文字セット（`a-k, m, n, p-z, 2-9` の32種、0/o/1/l を除外）で5文字のランダムIDを生成する。衝突時は再生成し、上限回数（例: 5回）を超えたらエラーを返す。

### パスワード

オリジナルは MD5 ハッシュをファイル名に埋め込んでいた（[save.cgi:441](../../../../original-source/difff-master/save.cgi#L441)）。移植版は KV レコード内に **ソルト付き SHA-256**（WebCrypto `crypto.subtle`）で `pwHash` を保持する。

PBKDF2 等の反復ハッシュは採用しない。3日で失効する共有リンクの削除キーであり、反復コストが Worker の CPU 制限（Free: 10ms）を直接圧迫するため。この割り切りは実装コメントとして明記する。

### 削除

オリジナルは `HTTP_REFERER` から対象ファイルを特定していた（[delete.cgi:21](../../../../original-source/difff-master/delete.cgi#L21)）。Referer は偽装・欠落しうるため、移植版では **明示的な `id` パラメータ** を POST body で受け取る方式に変更する。

### 濫用対策

- 保存時の入力上限: A + B 合計 200KB（KV value サイズの実用上限を踏まえた設定）。
- ID 衝突時の再生成上限を超えたらエラー。

## 7. ルーティング設計

`.htaccess` の rewrite（`/nw4c6.html` → `data/nw4c6.html`）は Worker 側のルーティングで代替する。

| パス | 処理 |
|---|---|
| `GET /`, `GET /en/` | 静的アセット（トップページ） |
| `POST /api/save` | `{lang, a, b, passwd}` → KV に TTL 3日で保存、`{id}` を返す |
| `POST /api/delete` | `{id, passwd}` → ハッシュ照合の上で KV から削除 |
| `GET /:id` | `[a-hjkmnp-z2-9]{5}` に合致した場合のみ Worker が処理。KV から元テキストを取得し、外殻 HTML に JSON として埋め込んで返す（ブラウザ側で差分を再描画） |
| `GET /:id.html` | `/:id` へ 301 リダイレクト（オリジナルの URL 形式との互換） |
| 上記以外 | 静的アセットへフォールスルー |

## 9. テスト戦略

- **ユニット**: トークナイザ（オリジナル正規表現の挙動の再現確認）、Myers（DPとの突き合わせによる最小性・復元性の property-based テスト）、行アライン、カウンタ。
- **ゴールデン**: オリジナル Perl 版（`diff -d` 使用）の出力とのバイト単位比較。差異があれば注記①の観点で記録する。
- **Worker**: `@cloudflare/vitest-pool-workers` で KV バインディングを含めて save/delete/page ルートを検証。
- **E2E**: Playwright で実ブラウザ上の Web Worker 経路（大きな入力でのキャンセル動作含む）、公開・削除フローを検証。

## 10. 実装フェーズ（概要）

1. **core** — 差分エンジン本体（tokenize/myers/align/count/render）とユニット・ゴールデンテスト
2. **client** — UI（フォーム、Web Worker連携、結果表示、カラーテーマ切替、印刷用表示）
3. **worker/KV** — 保存・削除・公開ページルーティング、Worker テスト
4. **i18n・デプロイ設定** — 日英メッセージカタログ、`wrangler.jsonc`、ビルド設定、E2E

詳細なステップ・タスク分解は次工程の実装計画（writing-plans）で定める。

## 11. 移植に伴う既知の逸脱一覧

| 項目 | オリジナル | 移植後 | 分類 |
|---|---|---|---|
| 差分計算エンジン | GNU diff (`diff -d`) | 自前 Myers 実装 | 技術的制約（FIFO/外部コマンド利用不可） |
| 行合わせロジック | `<$>` 複製による後処理 | ops からの直接構築 | 意図的改善（§5 注記②） |
| パスワードハッシュ | MD5（ファイル名埋め込み） | ソルト付き SHA-256（レコード内） | セキュリティ改善 |
| 削除時の対象特定 | `HTTP_REFERER` | 明示的な `id` パラメータ | セキュリティ改善（Referer偽装対策） |
| 保存先 | ファイルシステム + symlink | Workers KV（TTL 3日） | 技術的制約（Workers はファイルシステム非対応） |
| UI/HTML/CSS | HTML 4.01、`<font>`タグ、固定レイアウト | レスポンシブ・ダークモード対応で再設計 | 合意済み方針（UIモダン化） |
